# ブラウザでの確認

ビルド不要の静的サイトなので、配信して開くだけで本番と同じものが見られる。

## 手順

1. ローカルサーバーを起動する（バックグラウンドで）。
   ```
   .claude/scripts/serve.sh 8935
   ```

2. Playwrightで開く。ブラウザは `/opt/pw-browsers/chromium` にプリインストール済み。
   `executablePath: "/opt/pw-browsers/chromium"` を明示し、**`playwright install` は実行しない**。

3. 見る順番
   - サイドバーの **記事 / スタンプ / ゲーム / 動画 / 掲示板** を順に押してタブが切り替わるか
   - 記事タブの中の **note / Brain / Zenn** サブタブ（他タブでは自動で隠れる）
   - 検索窓に文字を入れて、意図したカードだけ残るか
   - **サイドバーの件数と、各セクションの `N articles` / `N games` / `N stamps` / `N videos` が一致しているか**
   - 幅900px以下でサイドバーがドロワーになり、ハンバーガー・スクリム・Escape・項目選択で閉じるか

4. スクリーンショットはスクラッチパッドに保存し、`Read` で目視確認する。

## ゲームのサムネイルを撮るとき

カードの画像は**そのゲームのタイトル画面のスクリーンショット**。

**この環境からは `*.github.io` に到達できないので、公開URLからは撮れない。**
撮りたいゲームのリポジトリをローカルに用意して配信し、そこから撮る。

- 単一HTML構成のゲーム（リズムゲーム等）… `python3 -m http.server` で配信
- Next.js のゲーム（名言タイピング）… そのリポジトリで `npm run dev`

撮ったら `img/<種別>_<連番>_<公開日>_<スラッグ>.png` に置く（`add-portfolio-item` スキル参照）。

## 既知の制約

- **外部サイトへの到達可否はセッションによって変わる（2026-09-03 更新）。**
  以前は「`*.github.io` に到達できない」としていたが、実際には
  `urllib` 経由・`WebFetch`・Playwright の `page.goto` のいずれも
  `*.github.io` / `youtube.com` / `zenn.dev` / `brain-market.com` に届いた実績がある。
  **まず直接アクセスを試し、失敗したときだけ「ローカルで確認したうえで公開URLでの実表示は
  未確認と明示する」に切り替える。** 到達できると決めつけず、かつ最初から諦めない。
- CSPで `connect-src 'none'` なので、fetch/XHRを使う機能はそもそも動かない設計。
  外部データが要る話が出たら、まずCSPを見る。
- **Google Fonts (`fonts.googleapis.com`) もこの環境からは読めない**
  （`net::ERR_CONNECTION_RESET`）。ローカル確認時のスクリーンショットは
  フォールバックのフォントで描画される。CSPの設定ミスではないので直そうとしないこと。
- カード画像は `loading="lazy"`。読み込み完了を待たずに `naturalWidth` を見ると
  「画像が壊れている」と誤判定する。**判定前に1.5秒ほど待つ**か、スクロールさせること。
